* In the initial version of this app, communication with TMDB was implemented on the browser. Of course, that exposed the API credentials. I decided not to push yet, keeping the mock data version live for a while, until I implement a solution using Vercel's serverless functions. My previous experience with serverless programming was when working on a small BMI calculator project (frontend vanilla JavaScript, backend Python and psycopg for db communication) which I deployed on Azure using what Microsoft refers to as Managed Functions. One of the purposes of this project is to improve my abilities in API endpoint design/implementation and serverless programming patterns. It became clear though that the underlying model of how web communication and API architecture work was still vague in my mind. That forced me to pause for a while. Instead of rushing ahead to a solution, I decided to take my time to learn. What I did to improve my knowledge (besides a lot of practice) was: 1) Initiated a new learning project (learning-api-endpoint-architecture) using Mat Pocock's /teach skill. You can find it in my GitHub account as a separate repo, and 2) Studying sources like the MDN documents for relevant material. That helped me to further clarify my understanding of serverless programming concepts and practices and finally implement a solution using Vercel functions that solves the problem.
